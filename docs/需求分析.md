## 1. 引言

### 1.2 编写目的

本文档旨在详细描述"基于 PostgreSQL 的数字图像集成管理系统"的功能与非功能需求，为后续的概要设计和详细设计提供依据。本系统是一个**桌面端应用程序**，主要面向拥有大量数字照片的个人用户，帮助他们高效地浏览、管理和展示图片。

本文档覆盖的主要内容包括：
- 系统的两大核心模块：**图片预览**和**幻灯片播放**
- 图片的增、删、查、改（复制、粘贴、重命名）操作
- 利用 PostgreSQL 数据库实现图片元数据的持久化存储
- 站在最终用户视角的完整**数据字典**

### 1.3 背景

| 项 | 说明 |
| :--- | :--- |
| 系统名称 | 基于 PostgreSQL 的数字图像集成管理系统 |
| 项目代号 | DIMS (Digital Image Management System) |
| 系统类型 | 单机桌面应用程序 |
| 任务提出者 | 面向对象程序设计与数据库系统课程教师 |
| 开发者 | 徐阳（组长）、毕振岚、陈厚华 |
| 最终用户 | 需要管理大量数字照片的普通个人用户 |
| 外部关系 | 独立系统，无外部子系统依赖（通过 JDBC 与 PostgreSQL 数据库交互） |
| IT标准与原则 | 遵循 Java 编码规范、MVC 架构模式、DAO 设计规范及数据库设计第三范式(3NF) |
| 开发环境 | Windows 11, Java 25, PostgreSQL 18.3 |

本项目同时满足《面向对象程序设计》和《数据库系统》两门课程的设计要求，实现"一石二鸟"。Java 方面重点考察 GUI 开发、面向对象设计和代码质量；数据库方面重点考察需求分析、数据库结构设计、SQL 编程（包括视图、索引、触发器、存储过程）以及数据库在非结构化多媒体数据处理中的应用。

### 1.4 用户特点

本系统的目标用户为**普通个人用户**，其特点如下：

| 特征 | 描述 |
| :--- | :--- |
| 计算机水平 | 具备基本的 Windows 操作能力，能使用鼠标、键盘进行常规操作 |
| 领域知识 | 无需专业图像处理知识，仅需了解"文件"、"文件夹"、"图片"等基本概念 |
| 使用频率 | 中等频率，通常在拍照后或整理照片时集中使用 |
| 期望 | 界面简洁直观、操作响应迅速、能高效地完成浏览和批量管理任务 |

### 1.5 假定与约束

1. 用户的计算机上已安装 Java 25 运行时环境
2. 用户的计算机上已安装并运行 PostgreSQL 18.3 数据库服务
3. 系统仅支持本地磁盘上的图片管理，不涉及网络传输
4. 图片文件尺寸范围：几十 KB 到几 MB，不处理超大尺寸原始 RAW 格式
5. 开发周期约2个月（2026年3月~5月）

### 1.7 术语定义及说明

| 术语 | 定义 |
| :--- | :--- |
| 缩略图 | 原始图片按比例等比缩小后的预览小图，保持原始宽高比不变形 |
| 目录树 | 以树形结构展示的计算机磁盘目录层级，仅显示文件夹不显示文件 |
| 幻灯片播放 | 以全屏或接近全屏的方式，按顺序自动或手动逐张展示图片 |
| 逻辑删除 | 不真正删除数据库记录，仅设置标记位将其隐藏，可恢复 |
| 物理删除 | 真正从磁盘和数据库中永久移除文件和记录，不可恢复 |
| 批量重命名 | 选中多张图片后，按照"名称前缀 + 起始编号 + 编号位数"的规则统一命名 |
| bytea | PostgreSQL 中用于存储二进制数据的数据类型 |
| 事务 | 数据库操作的最小逻辑单元，保证要么全部成功要么全部回滚 |

## 2. 功能需求

### 2.1 系统范围

本系统是一个**单机桌面图片管理应用程序**，旨在为个人用户提供：

1. **便捷的图片浏览**：以目录树导航 + 缩略图预览的方式，快速定位和查看图片
2. **灵活的图片管理**：支持选中、删除、复制、粘贴、重命名（含批量重命名）
3. **沉浸的幻灯片展示**：支持手动/自动切换、放大/缩小的图片展示模式
4. **可靠的数据持久化**：利用 PostgreSQL 数据库记录图片元数据和操作日志

│            数字图像集成管理系统 (DIMS)             │

### 2.4 需求分析

#### 2.4.1 目录树导航

**功能描述**

| 项 | 内容 |
|---|---|
| 功能编号 | FR-001 |
| 功能需求 | 用户希望在界面左侧看到一棵"文件夹树"，类似于 Windows 资源管理器，能够展开、折叠各级文件夹，从而定位到存放图片的目录。树中只显示目录（文件夹），不直接显示文件。 |

**业务建模（用例图描述）**

```
┌────────────┐         ┌─────────────────────┐
│   普通用户  │────────→│  UC-001 浏览目录树   │
└────────────┘         └─────────────────────┘
                              │
                       ┌──────┴──────┐
                       ▼             ▼
              «include»         «include»
         ┌──────────────┐  ┌──────────────┐
         │ 展开/折叠目录 │  │ 选中目录     │
         └──────────────┘  └──────────────┘
```

**用例描述**

| 描述对象 | 描述内容 |
| :--- | :--- |
| 标识符 | UC-001 |
| 说明 | 用户在界面左侧的目录树区域，通过点击展开/折叠按钮浏览磁盘目录结构，并点击某个目录以查看其中的图片 |
| 参与者 | 普通用户 — 具备基本计算机操作能力 |
| 频度 | 每次使用系统时都会用到，频率高 |
| 状态 | 通过审查 |
| 前置条件 | 1. 应用程序已启动 2. 本地磁盘存在可访问的目录 |
| 后置条件 | 1. 右侧预览区显示该目录下的所有图片缩略图 2. 底部状态栏显示图片数量和总大小 |
| 被扩展的用例 | 无 |
| 被包含的用例 | UC-001a 展开/折叠目录、UC-001b 选中目录 |
| 基本操作流程 | 1. 用户在目录树中看到磁盘根目录（如 C:\, D:\） 2. 用户点击目录前的展开箭头，查看子目录 3. 用户点击某个目录名称，该目录高亮选中 4. 系统扫描该目录下所有支持格式的图片文件 5. 系统在右侧预览区以缩略图形式展示所有图片 6. 系统在底部状态栏显示"共 X 张图片，总大小 Y" |
| 可选操作流程 | 1. 若目录下没有支持格式的图片，预览区显示空白，状态栏显示"共 0 张图片" 2. 若目录不可访问（权限不足），显示提示信息 |
| 修改历史记录 | 2026-04-03 徐阳 初始版本 |

**用户界面**

目录树区域位于主界面左侧，宽度约占整个窗口的 1/4 ~ 1/3。目录树的根节点为"我的电脑"，下级为各磁盘根目录（C:\, D:\ 等），继续向下展开为各级子目录。当目录层级较深或子目录较多时，该区域可纵向和横向滚动。选中的目录以高亮背景色标识。

**功能描述**

| 项 | 内容 |
|---|---|
| 功能编号 | FR-004 |
| 功能需求 | 用户选中图片后，可以删除这些图片。系统在删除前必须弹出确认对话框，防止误删。删除后预览区应立即更新。 |

**用例描述**

| 描述对象 | 描述内容 |
| :--- | :--- |
| 标识符 | UC-004 |

| 基本操作流程 | 1. 用户选中图片，右键选择"删除"或按 Delete 键 2. 系统弹出确认对话框："确定要删除选中的 N 张图片吗？" 3. 用户点击"确认" 4. 系统删除图片文件，更新数据库记录 5. 预览区刷新，移除已删除的缩略图 |
| 可选操作流程 | 用户点击"取消"，操作中止，无任何变化 |

#### 2.4.5 图片复制与粘贴

**功能描述**

| 项 | 内容 |
|---|---|

## 3. 非功能需求

### 3.1 性能要求

#### 3.1.1 精度

- 图片文件大小：显示精度为 KB（小于 1 MB 时）或 MB（大于等于 1 MB 时），保留两位小数
- 缩略图缩放比例：保持原始宽高比，精度无损
- 幻灯片缩放比例：以当前显示百分比展示（如 65%、100%、150%）

#### 3.1.2 时间特性要求

| 操作 | 响应时间要求 |
| :--- | :--- |
| 目录树展开/折叠 | ≤ 0.5 秒 |
| 缩略图加载（单个目录） | ≤ 3 秒（100张图片以内） |
| 图片选中/取消选中 | ≤ 0.1 秒（即时响应） |
| 删除操作（含确认框） | ≤ 1 秒 |
| 批量重命名（100张以内） | ≤ 2 秒 |
| 幻灯片图片切换 | ≤ 0.5 秒 |

#### 3.1.3 输入输出要求

**输入**：
- 鼠标操作：单击、双击、右击、拖拽、Ctrl+单击
- 键盘操作：Delete 键（删除）、Ctrl+C（复制）、Ctrl+V（粘贴）
- 文本输入：重命名时的文件名称（最多 100 个可见字符）、批量重命名参数

**输出**：
- 图形输出：缩略图网格、大图展示、目录树、状态栏文本
- 格式支持：.JPG, .JPEG, .GIF, .PNG, .BMP（不区分大小写）

### 3.2 数据管理能力要求

| 指标 | 目标值 |
| :--- | :--- |
| 单目录最大图片数量 | 可管理 1000 张以上 |
| 单个图片文件大小 | 支持几十 KB 到 20 MB |
| 数据库缩略图存储 | 每张缩略图约 10~50 KB（bytea 存储） |
| 操作日志保留期限 | 永久保留（数据库记录） |
| 预估数据增长 | 每月新增约 500~2000 条图片记录 |

### 3.3 安全保密性要求

- 删除操作前必须进行二次确认，防止误删
- 批量重命名操作在数据库事务中执行，任何一步失败则全部回滚，保证数据一致性
- 数据库连接密码保存在配置文件中，不硬编码在源代码里

### 3.4 灵活性要求

- 支持的图片格式列表可扩展（通过配置）
- 数据库连接参数可通过配置文件修改
- 缩略图大小可调整
- 幻灯片播放间隔可设定
- 目录树根节点可配置（限定浏览范围）

### 3.5 其他专门要求

- 界面应简洁美观，参考"美图看看"的布局风格
- 支持 Windows 操作系统（主要平台）
- 应用退出时应正确关闭所有数据库连接，避免资源泄漏
- 所有用户可见的异常状况均需提供友好的错误提示，而非技术性堆栈信息
