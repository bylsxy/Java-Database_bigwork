第一部分：项目宏观概览
1. 项目是干什么的？ 这是一个基于桌面端的数字图像集成管理系统。简单来说，它就像是你电脑上的“智能相册”（比如 Mac 的照片 App 或者 Windows 的照片应用）。 它能做到：

扫描你电脑上的文件夹，把图片信息（比如大小、长宽、缩略图）存到数据库里。
提供图片的浏览、幻灯片播放（还可以加背景音乐）、简单的图片编辑。
最大亮点：接了外部大模型的 AI API，能自动识别图片里有什么（比如“汽车”、“瀑布”），打上标签，然后你可以通过关键字搜索图片。
还可以支持连接 WebDAV 云盘。
2. 核心技术栈

开发语言：Java 21（现代的 Java 版本）
UI 界面：JavaFX（Java官方的桌面应用开发框架）
数据库：PostgreSQL 18.3（一个强大的关系型数据库）
依赖/构建工具：Maven（帮你下载第三方包、打包代码的工具）
第二部分：项目目录结构
你在 IDEA 或 VSCode 里打开项目，会看到如下的树状结构。你向老师展示时，可以按照这个顺序介绍：

pom.xml：这是 Maven 的配置文件。项目的“采购清单”。里面写了我们需要用到什么第三方工具（比如连接数据库的 postgresql，做 HTTP 请求发给 AI 的 okhttp，解析 JSON 的 jackson 等）。
sql/：数据库脚本文件夹。
schema.sql：建表脚本（里面全都是 CREATE TABLE，用来创建空表）。
data.sql：初始数据脚本（里面是 INSERT，可以用来写入一些默认测试数据）。
src/main/：这是我们的核心战场，分为 java 和 resources 两块。
java/com/imagemanager/：全都是你写的 Java 后端代码（下文详讲）。
resources/：存放所有非 Java 代码的资源文件。
fxml/：界面布局文件（JavaFX 用 XML 格式来画界面，比如按钮放哪、多大，都在这里）。
css/：界面的样式表（像网页一样，用 CSS 让界面变好看）。
config/ 和 music/：存放配置文件和幻灯片背景音乐。
logback.xml：日志配置文件（决定控制台打印什么颜色的日志、存到哪个文件）。
第三部分：数据库设计详解 (针对 schema.sql)
数据库就像是项目的“记忆中枢”。我们用的是关系型数据库，表和表之间是有联系的。你要让老师知道你的表设计得很规范：

1. 目录和图片表（最基础的两张表）

directories（目录表）
id：主键。
dir_name / dir_path：文件夹名字（比如“我的照片”）和完整路径（D:\我的照片）。
parent_id：父目录的 ID。重点：通过这个字段，表可以自己关联自己，在数据库里形成一个“树状结构”（比如 D盘 下面有 文件夹A，文件夹A 下面有 文件夹B）。
images（图片表，核心表）
id、file_name（文件名）、file_path（文件路径）。
directory_id：外键，关联上面的目录表（这说明图片是放在哪个文件夹里的）。
file_size、width、height、format：图片的元数据。
thumbnail：缩略图，类型是 BYTEA（二进制）。重点：我们把缩小后的图片直接以二进制存在数据库里，这样界面加载极快，不用每次都去读硬盘里几十MB的大图。
file_hash：文件的防伪指纹（SHA-256），防止同一张图片被处理两遍。
ai_processed：是否已经被 AI 处理过。
2. AI 标签分类体系（多对多关系表）

tag_categories（标签分类表）：定义了大类，比如“人物”、“风景”、“食物”。
tags（标签表）：具体的标签，比如“乔布斯”、“瀑布”、“苹果”。有一个外键 category_id 关联大类。
image_tags（图片-标签关联表）：重点：一张图片可以有多个标签，一个标签也可以对应多张图片。所以我们必须建一张“中间表”来关联 images 和 tags。它包含 image_id、tag_id，以及 confidence（AI 识别的置信度，即 AI 有多大把握觉得它是这个标签）。
ai_analysis_results：直接把 AI 返回的那一长串复杂的 JSON 文本缓存在这里，备查。
3. 其它辅助表

operation_logs：操作日志表。用户重命名、删除了图片，全记录在这里，方便审计。
app_settings：软件设置表（存你的 API Key、默认扫描路径等）。
search_history：用户的搜索历史。
image_versions / image_edit_operations：图片的历史版本记录表，支持图片编辑后“撤销”或恢复原状。
第四部分：Java代码架构与类功能 (MVC 架构)
打开 src/main/java/com/imagemanager，里面的包（文件夹）分工明确，这就是经典的 MVC (Model-View-Controller) 设计模式的变种。我们逐个击破：

1. 入口文件

Launcher.java：给 JVM（Java虚拟机）看的入口，主要是为了解决打包后 JavaFX 启动报错的问题。它只做一件事：调用 App.main()。
App.java：真正的程序入口。它负责连接数据库、加载主界面的 FXML 布局，把窗口弹出来。
2. model 包（模型层，也就是实体类）

这里面的类（如 ImageFile， DirectoryNode， Tag， AppSetting）统称为 POJO（普通Java对象）。
它们没有任何逻辑，仅仅是对数据库表的一一映射。比如 ImageFile.java 里就定义了 id， fileName， width 等属性，用来在内存中临时抱着从数据库查出来的数据。
3. dao 包（Data Access Object 数据访问层）

职责：专门负责和 PostgreSQL 数据库打交道（写 SQL 语句）。
DatabaseConnection.java：使用了 HikariCP 数据库连接池。负责和数据库建立连接。
ImageDao / ImageDaoImpl：接口和它的实现类。里面全都是 insertImage()， getImageById()， deleteImage() 这样的方法。里面包着 SELECT * FROM images 这类 SQL 语句。
4. service 包（业务逻辑层）

职责：整个软件的“大脑”。它向下调用 DAO 层去查数据，向上给 Controller 层提供现成的结果。
ImageService：处理图片相关的复杂逻辑。
AiTagStorageService：把 AI 识别出来的乱七八糟的 JSON，解析成我们可以存进库的标签。
SearchService：处理用户的关键字搜索或 SQL 搜索。
DirectoryScanner / ScanTask（在 scanner 包）：一个后台线程，去递归遍历硬盘上的文件夹，找出所有的 .jpg， .png 文件。
5. controller 包（控制层 / 视图逻辑）

职责：每个 FXML 界面（View）都对应这里的一个 Controller。它负责两件事：用户点了一个按钮，它要去触发 service；service 传回来数据，它要把数据塞到界面的表格或列表里显示出来。
MainController：主界面控制器，最复杂。管左边的目录树、中间的图片列表、右边的搜索框。
ImageViewerController：双击图片放大看的界面。
SettingsController：设置界面（填 API key 等）。
WelcomeDialogController：第一次打开软件时的“小白引导界面”。
6. 其他核心包

ai 包：负责网络通信。通过 OkHttp 把图片转化为 Base64 或者直接发 URL 给外部的 AI 模型（比如智谱、阿里通义等兼容 OpenAI 接口的模型），获取识别结果。
util 包：工具人工厂。ImageUtil 用来把大图片压缩成缩略图；FileUtil 用来读写文件；AlertUtil 专门用来弹报错或提示框。
第五部分：核心业务流程串讲（答辩怎么讲故事）
答辩时，老师最喜欢听你描述一个完整的流程（也就是数据是怎么流动的）。你可以准备下面这三个故事：

流程故事1：软件启动并扫描文件夹

“老师您好，当用户打开软件时，App.java 会先向 DatabaseConnection 申请建立数据库连接。如果查到用户是第一次用，会弹出 WelcomeDialog 引导用户选一个本地文件夹。选好后，ScanTask 开启后台多线程扫描。它每找到一张图片，就用 ImageUtil 生成一个很小的二进制缩略图，然后由 ImageDao 执行 INSERT 语句存入 images 表里。这样用户在界面上就能极快地看到所有图片了。”

流程故事2：AI 自动打标签

“当用户选中一张图片点击‘AI识别’时，controller 会把图片传给 ai 包下的 OpenAICompatibleService。这个 Service 使用 OkHttp 构造一个网络请求发给外部大模型。大模型返回一段 JSON 数据后，AiTagStorageService 会用 Jackson 库去解析这个 JSON，提取出‘人物’、‘场景’等关键字。最后，通过 TagDao 更新 tags 和 image_tags（图片关联表），完成自动分类。”

流程故事3：双击查看与幻灯片

“在主界面，用户双击一个缩略图，MainController 就会打开 ImageViewerController 的 FXML 视图。同时根据数据库里存的 file_path，去本地硬盘加载那张高清大图显示。如果点击幻灯片播放，SlideshowController 会接管，并利用 MusicService（依赖 JavaFX Media 组件）在后台播放背景音乐，定时切换下一张图片。”

💡 答辩必背 QA 防身指南：
Q1：为什么图片文件存在本地硬盘，而要把“缩略图”存到数据库的 BYTEA 字段里？ 答：如果每次展示图片列表都去硬盘读几十MB的原图并临时压缩，界面会非常卡顿。把几十KB的缩略图存在数据库里，配合 PostgreSQL 的高效查询，我可以一次性把 100 张缩略图瞬间拉进内存并渲染在界面上，极大地提升了用户体验。

Q2：如果用户在电脑上偷偷把照片删了或者重命名了，你的软件会崩溃吗？ 答：我们在数据库里存了 file_path 和 file_hash。如果在打开大图时发现文件不存在，FileUtil 会抛出异常，AlertUtil 会给用户友好的弹窗提示文件已丢失。后续可以做一个同步校验功能来清理数据库里的失效记录。

Q3：为什么不直接在 Controller 里写数据库查询，而要分 Dao 层和 Service 层？ 答：这是为了代码的高内聚低耦合。Dao 层专门写 SQL，哪天我们想把 PostgreSQL 换成 MySQL，只改 Dao 层就行；Service 层处理业务逻辑，比如解析 AI 的 JSON；Controller 只管按钮点击和界面更新。这样代码好维护，结构清晰，别人看我的代码也一目了然。
