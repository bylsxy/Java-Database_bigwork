## 1. 引言

### 1.2 编写目的

本文档旨在详细描述"基于 PostgreSQL 的数字图像集成管理系统"的功能与非功能需求，为后续的概要设计和详细设计提供依据。本系统是一个**桌面端应用程序**，主要面向拥有大量数字照片的个人用户（以下称"机主"），帮助他们高效地浏览、管理和展示图片。

本文档覆盖的主要内容包括：
- 系统的七大核心模块：**图片预览**、**幻灯片播放**、**AI图像识别与标签**、**智能搜索(NL2SQL)**、**图片编辑与版本历史**、**幻灯片增强（多选+音乐）**、**云端/网盘集成**
- 图片的基本的CURD操作
- AI驱动的图像自动分类、标签管理（含用户手动修正）和自然语言查询（含同义词映射）
- 利用 PostgreSQL 数据库实现图片元数据、AI标签、版本历史、搜索记录的持久化存储
- 站在最终用户视角的完整**数据字典**
- 日后将支持更多的多媒体格式

### 1.5 假定与约束

1. 用户的计算机上已安装 Java 26 运行时环境
2. 用户的计算机上已安装并运行 PostgreSQL 18.3 数据库服务
3. AI图像识别功能需要网络连接（调用OpenAI兼容API），其余功能可离线使用
4. 图片文件尺寸范围：几十 KB 到几 MB，不处理超大尺寸原始 RAW 格式
5. 开发周期视项目难度以及反响度而定(计划为2026.03-2026.06初)
6. 开发小组交流工具：Github发布issue、微信群
7. AI API 需要用户自行获取密钥（系统默认配置通义千问VL，有免费额度）
8. 云端集成（WebDAV/网盘）为可选功能，不影响核心使用

## 2. 功能需求

### 2.1 系统范围

本系统是一个**智能桌面图片管理应用程序**，旨在为机主提供：

1. **便捷的图片浏览**：以目录树导航 + 缩略图预览的方式，快速定位和查看图片
2. **灵活的图片管理**：支持选中、删除、复制、粘贴、重命名（含批量重命名）
3. **AI智能分类**：嵌入图像识别AI自动分析图片内容，生成超细粒度多分类标签（按主体重要性排序），支持用户查看与手动修正
4. **自然语言搜索**：支持关键词搜索和AI驱动的NL2SQL自然语言查询,未来计划升级到多模态的语义相似度检索
5. **图片编辑与版本管理**：裁切、画笔、文字、箭头、矩形标注，每次编辑自动创建版本快照
6. **沉浸的幻灯片展示**：支持多选播放、背景音乐、可配置间隔的图片展示模式
7. **云端集成**：可选的WebDAV/网盘连接，支持云端图片浏览
8. **可靠的数据持久化**：利用 PostgreSQL 数据库记录元数据、标签、版本、日志
9. **未来的想法**: 多租户，统一的资源定位符，AST命令快捷操作

## 3. 非功能需求

### 3.1 性能要求

#### 3.1.1 精度

- 图片文件大小：显示精度为 KB（小于 1 MB 时）或 MB（大于等于 1 MB 时），保留两位小数
- 缩略图缩放比例：保持原始宽高比，精度无损
- 幻灯片缩放比例：以当前显示百分比展示（如 65%、100%、150%）
- AI标签置信度：由AI模型返回，系统不做二次处理

#### 3.1.2 时间特性要求

| 操作 | 响应时间要求 |
| :--- | :--- |
| 目录树展开/折叠 | ≤ 0.5 秒 |
| 缩略图加载（单个目录） | ≤ 3 秒（100张图片以内） |
| 图片选中/取消选中 | ≤ 0.1 秒（即时响应） |
| 删除操作（含确认框） | ≤ 1 秒 |
| 批量重命名（100张以内） | ≤ 2 秒 |
| 幻灯片图片切换 | ≤ 0.5 秒 |
| 关键词搜索响应 | ≤ 1 秒 |
| AI智能搜索（NL2SQL） | ≤ 5 秒（含API调用） |
| 单张AI图像识别 | ≤ 10 秒（受API限速） |
| 版本保存 | ≤ 2 秒 |

#### 3.1.3 输入输出要求

**输入**：
- 鼠标操作：单击、双击、右击、拖拽、Ctrl+单击
- 键盘操作：Delete 键（删除）、Ctrl+C（复制）、Ctrl+V（粘贴）
- 文本输入：重命名参数、搜索查询、AI API配置、文字标注
- 文件输入：API测试示例图片

**输出**：
- 图形输出：缩略图网格、大图展示、目录树、编辑器Canvas、版本时间轴
- 音频输出：幻灯片背景音乐（MP3）
- 格式支持：.JPG, .JPEG, .GIF, .PNG, .BMP（不区分大小写）

### 3.2 数据管理能力要求

| 指标 | 目标值 |
| :--- | :--- |
| 单目录最大图片数量 | 可管理 1000 张以上 |
| 单个图片文件大小 | 支持几十 KB 到 20 MB |
| 数据库缩略图存储 | 每张缩略图约 10~50 KB（bytea 存储） |
| AI标签存储 | 每张图片约 10~30 个标签，多个分类（可扩展），含用户自定义标签 |
| 版本历史存储 | 每张图片最多保留 50 个版本快照 |
| 搜索历史保留 | 最近 500 条搜索记录 |
| 操作日志保留期限 | 永久保留（数据库记录）（用户可以决定是否删除） |
| 预估数据增长 | 每月新增约 50~200 条图片元数据记录 |

### 3.3 安全保密性要求

- 删除操作前必须进行二次确认，防止误删
- 批量重命名操作在数据库事务中执行，任何一步失败则全部回滚
- 可以增设管理密码与用户权限系统,保存在配置文件中，不硬编码在源代码里,同时,一定保证采用加密,在第一次启动的时候提醒用户及时修改密码
- AI API密钥存储在数据库app_settings表中，不明文显示在界面（PasswordField）
- NL2SQL安全校验：仅允许SELECT语句，禁止DROP/DELETE/UPDATE/INSERT/ALTER等危险关键词
- AI搜索生成的SQL语句记录到search_history表，便于审计
- [计划]路径防穿透，保证数据库记录的路径安全


### 3.4 灵活性要求

- 支持的图片格式列表可扩展（通过配置）
- 数据库连接参数可通过配置文件修改
- 缩略图大小可调整
- 幻灯片播放间隔可在设置页面配置（持久化到数据库）
- AI API服务商可切换（支持任何OpenAI兼容格式的API）
- 扫描目录可在设置页面随时修改
- 云端集成为可选功能，不影响核心使用
- [计划]用户可以自行选择数据源（目前计划支持PostgreSQL以及SQLite）
- [计划]用户可以自行选择是否保留缩略图或者搜索元数据进入数据库，以实现读取性能与存储空间大小占用的平衡
- [计划]多后端需求，可以使用Web端而不仅仅是GUI端进行管理

### 3.5 其他专门要求

- 界面应简洁美观，参考"美图看看"的布局风格
- 支持 Windows 操作系统
- 应用退出时应正确关闭所有数据库连接和音乐播放，避免资源泄漏
- 所有用户可见的异常状况均需提供友好的错误提示，而非技术性堆栈信息
- AI后台扫描不阻塞UI，使用独立线程和进度反馈
