## 1. 引言

### 1.1 编写目的

本文档是"基于 PostgreSQL 的数字图像集成管理系统"的概要设计说明书。在需求分析的基础上，确定系统的整体架构、模块划分、接口设计和数据库结构设计，为详细设计和编码实现提供指导。

### 1.2 背景

本系统是一个 JavaFX 桌面应用程序，使用 PostgreSQL 18.3 作为数据持久化层，实现本地数字图片的浏览、管理和幻灯片播放功能。系统采用三层架构（DAO → Service → Controller/View），不依赖任何 Web 框架。

### 2.2 分层设计原则

| 层 | 职责 | 原则 |
| :--- | :--- | :--- |
| **表示层** | 界面布局（FXML）、用户交互响应（Controller）、样式（CSS） | 只负责展示和收集用户输入，不含任何业务逻辑 |
| **业务逻辑层** | 事务管理、批量操作协调、业务规则校验（如文件名合法性） | 面向接口编程，使用 interface 定义约定 |
| **数据访问层** | 封装所有 SQL 操作、PreparedStatement 参数化查询 | 只负责数据库读写，不含业务判断 |
| **数据库层** | 数据存储、索引优化、触发器自动记录日志、存储过程生成报表 | 利用数据库自身能力保障数据完整性 |

## 4. 数据库设计

### 4.1 数据库选择理由

选择 **PostgreSQL 18.3** 作为数据库管理系统，理由如下：

1. **bytea 数据类型**：原生支持二进制大对象存储，适合保存图片缩略图
2. **递归查询（WITH RECURSIVE）**：天然支持树形目录结构的递归查询
3. **事务支持**：完善的 ACID 事务保证批量重命名等操作的一致性
4. **丰富的索引类型**：B-Tree 索引优化海量数据检索
5. **触发器与存储过程**：服务端业务逻辑，自动记录操作日志并生成统计报表
6. **开源免费**：满足课程设计要求，无授权费用

### 4.2 实体-联系分析（ER 设计）

#### 4.2.1 实体识别

| 实体 | 来源需求 | 说明 |
| :--- | :--- | :--- |
| **目录 (Directory)** | FR-001 目录树导航 | 本地磁盘的文件夹，以树形层级组织 |
| **图片 (Image)** | FR-002 缩略图预览 | 磁盘上的图片文件及其元数据 |
| **操作日志 (OperationLog)** | FR-004~006 删除/复制/重命名 | 记录用户对图片的每次操作 |

#### 4.2.2 联系分析

| 联系 | 类型 | 实体 | 来源需求 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 目录-子目录 | 一对多 (1:N) | Directory → Directory | FR-001 | 一个目录下有多个子目录（自引用） |
| 目录-图片 | 一对多 (1:N) | Directory → Image | FR-001, FR-002 | 一个目录下有多张图片 |
| 图片-日志 | 一对多 (1:N) | Image → OperationLog | FR-004~006 | 一张图片可有多条操作记录 |

### 4.3 关系模式设计

#### 4.3.1 directories 表

| 字段名 | 数据类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | SERIAL | PRIMARY KEY | 目录唯一标识 |
| dir_name | VARCHAR(255) | NOT NULL | 目录名称 |
| dir_path | TEXT | NOT NULL, UNIQUE | 目录完整路径（唯一） |
| parent_id | INTEGER | REFERENCES directories(id) ON DELETE CASCADE, 允许 NULL | 父目录 ID，根目录为 NULL |
| created_at | TIMESTAMP | DEFAULT NOW() | 创建时间 |

**空值率估算**：parent_id 字段仅在磁盘根目录时为 NULL，约占 2~5 条（取决于磁盘数），占比极低（< 1%）。

#### 4.3.2 images 表

| 字段名 | 数据类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | SERIAL | PRIMARY KEY | 图片唯一标识 |
| file_name | VARCHAR(255) | NOT NULL | 文件名（含扩展名） |
| file_path | TEXT | NOT NULL | 文件完整路径 |
| directory_id | INTEGER | NOT NULL, REFERENCES directories(id) ON DELETE CASCADE | 所属目录 |
| file_size | BIGINT | | 文件大小（字节） |
| width | INTEGER | | 图片宽度（像素） |
| height | INTEGER | | 图片高度（像素） |
| format | VARCHAR(10) | | 格式：JPG/JPEG/GIF/PNG/BMP |
| thumbnail | BYTEA | | 缩略图二进制数据 |
| created_at | TIMESTAMP | DEFAULT NOW() | 首次录入数据库时间 |
| modified_at | TIMESTAMP | DEFAULT NOW() | 最后修改时间 |
| is_deleted | BOOLEAN | DEFAULT FALSE | 逻辑删除标记 |

**空值率估算**：
- thumbnail 字段：首次加载时可能为 NULL，后续生成后更新，运行一段时间后空值率趋近 0%
- width/height：需要读取图片元信息才能获得，可能初始为 NULL，空值率约 5%
- file_size：正常情况不为 NULL，空值率约 0%
- 整个数据库的空值率估算：约 2~3%

#### 4.3.3 operation_logs 表

| 字段名 | 数据类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | SERIAL | PRIMARY KEY | 日志唯一标识 |
| image_id | INTEGER | REFERENCES images(id) ON DELETE SET NULL | 关联图片 |
| operation_type | VARCHAR(20) | NOT NULL | 操作类型：RENAME/DELETE/COPY/PASTE |
| old_value | TEXT | | 操作前的值（如旧文件名、旧路径） |
| new_value | TEXT | | 操作后的值（如新文件名、新路径） |
| operated_at | TIMESTAMP | DEFAULT NOW() | 操作时间 |

**空值率估算**：old_value 和 new_value 在某些操作类型下可能为空（如 DELETE 的 new_value），约 20~30%。

| :--- | :--- | :--- | :--- | :--- |

### 4.5 视图设计

#### v_active_images（活跃图片视图）

**目的**：过滤逻辑删除的图片，简化查询。用户在界面上看到的缩略图列表通过此视图获取。

```sql
CREATE VIEW v_active_images AS
SELECT i.id, i.file_name, i.file_path, i.directory_id, 
       i.file_size, i.width, i.height, i.format, i.thumbnail,
       i.created_at, i.modified_at,
       d.dir_name, d.dir_path
FROM images i
JOIN directories d ON i.directory_id = d.id
WHERE i.is_deleted = FALSE;
```

#### v_directory_stats（目录统计视图）

**目的**：提供每个目录的图片数量和总大小统计，用于界面底部的状态栏显示。

```sql
CREATE VIEW v_directory_stats AS
SELECT d.id AS directory_id, d.dir_name, d.dir_path,
       COUNT(i.id) AS image_count,
       COALESCE(SUM(i.file_size), 0) AS total_size
FROM directories d
LEFT JOIN images i ON d.id = i.directory_id AND i.is_deleted = FALSE
GROUP BY d.id, d.dir_name, d.dir_path;
```

### 4.6 触发器设计

#### 自动记录操作日志触发器

**目的**：每当 images 表发生 UPDATE（重命名）或 DELETE（物理删除）操作时，自动向 operation_logs 表中写入一条记录，无需应用层手动插入日志。这是课程设计要求的重要评分点。

```sql
-- 触发器函数：INSERT 操作日志
CREATE OR REPLACE FUNCTION fn_log_image_insert()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO operation_logs (image_id, operation_type, new_value)
    VALUES (NEW.id, 'INSERT', NEW.file_name);
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 触发器函数：UPDATE 操作日志（捕获重命名）
CREATE OR REPLACE FUNCTION fn_log_image_update()
RETURNS TRIGGER AS $$
BEGIN
    -- 文件名变更时记录重命名操作
    IF OLD.file_name IS DISTINCT FROM NEW.file_name THEN
        INSERT INTO operation_logs (image_id, operation_type, old_value, new_value)
        VALUES (NEW.id, 'RENAME', OLD.file_name, NEW.file_name);
    END IF;
    -- 逻辑删除时记录删除操作
    IF OLD.is_deleted = FALSE AND NEW.is_deleted = TRUE THEN
        INSERT INTO operation_logs (image_id, operation_type, old_value)
        VALUES (NEW.id, 'DELETE', OLD.file_name);
    END IF;
    -- 更新 modified_at 时间戳
    NEW.modified_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 触发器函数：DELETE 操作日志（物理删除）
CREATE OR REPLACE FUNCTION fn_log_image_delete()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO operation_logs (image_id, operation_type, old_value)
    VALUES (OLD.id, 'HARD_DELETE', OLD.file_name);
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

-- 绑定触发器
CREATE TRIGGER trg_image_after_insert AFTER INSERT ON images
    FOR EACH ROW EXECUTE FUNCTION fn_log_image_insert();
    
CREATE TRIGGER trg_image_before_update BEFORE UPDATE ON images
    FOR EACH ROW EXECUTE FUNCTION fn_log_image_update();
    
CREATE TRIGGER trg_image_after_delete AFTER DELETE ON images
    FOR EACH ROW EXECUTE FUNCTION fn_log_image_delete();
```

### 4.7 存储过程设计

#### 按月统计报表存储过程

**目的**：生成按月份统计的图片操作报表，展示每月的新增、删除、重命名数量。

```sql
CREATE OR REPLACE PROCEDURE sp_monthly_report(
    IN p_year INTEGER,
    IN p_month INTEGER,
    INOUT p_result REFCURSOR
)
LANGUAGE plpgsql AS $$
BEGIN
    OPEN p_result FOR
    SELECT 
        operation_type,
        COUNT(*) AS operation_count,
        DATE_TRUNC('day', operated_at) AS operation_date
    FROM operation_logs
    WHERE EXTRACT(YEAR FROM operated_at) = p_year
      AND EXTRACT(MONTH FROM operated_at) = p_month
    GROUP BY operation_type, DATE_TRUNC('day', operated_at)
    ORDER BY operation_date, operation_type;
END;
$$;
```

#### 目录统计存储过程

**目的**：计算指定目录（含子目录）的图片总数和总大小，用于生成目录空间占用报表。

```sql
CREATE OR REPLACE PROCEDURE sp_directory_report(
    IN p_directory_id INTEGER,
    INOUT p_total_images INTEGER DEFAULT 0,
    INOUT p_total_size BIGINT DEFAULT 0,
    INOUT p_subdirectory_count INTEGER DEFAULT 0
)
LANGUAGE plpgsql AS $$
BEGIN
    -- 利用递归 CTE 统计目录及其所有子目录
    SELECT COUNT(i.id), COALESCE(SUM(i.file_size), 0)
    INTO p_total_images, p_total_size
    FROM images i
    WHERE i.is_deleted = FALSE
      AND i.directory_id IN (
          WITH RECURSIVE dir_tree AS (
              SELECT id FROM directories WHERE id = p_directory_id
              UNION ALL
              SELECT d.id FROM directories d
              JOIN dir_tree dt ON d.parent_id = dt.id
          )
          SELECT id FROM dir_tree
      );
    
    -- 统计子目录数量
    SELECT COUNT(*) INTO p_subdirectory_count
    FROM (
        WITH RECURSIVE dir_tree AS (
            SELECT id FROM directories WHERE parent_id = p_directory_id
            UNION ALL
            SELECT d.id FROM directories d
            JOIN dir_tree dt ON d.parent_id = dt.id
        )
        SELECT id FROM dir_tree
    ) sub;
END;
$$;
```

### 4.8 递归查询设计

**目的**：利用 PostgreSQL 的 `WITH RECURSIVE` CTE 实现目录树的层级查询，这是课程设计的重要展示点。

```sql
-- 查询某个目录的所有后代目录（构建完整目录树）
WITH RECURSIVE directory_tree AS (
    -- 锚点：指定的根目录
    SELECT id, dir_name, dir_path, parent_id, 0 AS depth
    FROM directories
    WHERE id = :root_id
    
    UNION ALL
    
    -- 递归：查找所有子目录
    SELECT d.id, d.dir_name, d.dir_path, d.parent_id, dt.depth + 1
    FROM directories d
    JOIN directory_tree dt ON d.parent_id = dt.id
)
SELECT * FROM directory_tree ORDER BY depth, dir_name;
```

### 4.10 面向变化的数据库设计考量

## 6. 外模式设计

外模式（External Schema）是数据库对特定用户或应用的可见视图。本系统为不同使用场景提供以下外模式：

### 外模式 1：图片浏览视图 (v_active_images)

**使用者**：图片预览模块
**用途**：获取某目录下所有未删除的图片信息
**包含字段**：图片ID、文件名、文件路径、所属目录ID、文件大小、宽高、格式、缩略图数据

### 外模式 2：目录统计视图 (v_directory_stats)

**使用者**：状态栏信息展示
**用途**：快速获取每个目录的图片数量和总大小
**包含字段**：目录ID、目录名、路径、图片总数、总大小

### 外模式 3：操作报表（存储过程 sp_monthly_report）

**使用者**：管理/统计功能
**用途**：生成按月统计的操作报表
**输出字段**：操作类型、操作次数、操作日期

## 7. 关键设计决策记录

| 决策 | 选择 | 理由 |
| :--- | :--- | :--- |
| 图片本体存储 | 文件系统（引用路径） | 原图 MB 级别，存数据库性能不佳；只存缩略图到 bytea |
| 缩略图存储 | bytea 字段 | 缩略图 10~50 KB，适合数据库存储，方便随元数据一起加载 |
| 删除策略 | 先逻辑删除，后物理清理 | 防误删，保留操作记录，可恢复 |
| 连接池 | HikariCP | 业界标准，性能最佳，配置简单 |
| 日志记录 | 触发器自动写入 | 比应用层手动插入更可靠，不会被遗漏 |
| 报表统计 | 存储过程 | 在数据库端计算，减少数据传输，体现数据库设计能力 |
| 目录树 | 递归 CTE | PostgreSQL 原生支持，性能好，代码简洁 |
