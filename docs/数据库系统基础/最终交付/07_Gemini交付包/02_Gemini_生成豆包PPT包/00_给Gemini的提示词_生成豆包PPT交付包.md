# 给 Gemini 的提示词：生成交给豆包的 PPT 制作包

你将收到一组课程设计资料。请不要直接生成 PPT 文件，而是为“豆包 PPT”准备一份完整的 PPT 生成交付包。我要把你输出的内容和相关资料再交给豆包，让豆包直接生成美观、专业、适合答辩的 PPT。

请先阅读我上传的教师任务书、评分依据图片、课程报告模板、重要答疑、需求分析正式版、概要设计、详细设计、当前报告草稿、当前 PPT 草稿、页面视觉图、真实界面截图、README、schema.sql 和关键代码。材料优先级如下：

1. 教师任务书、评分依据图片、报告通知和重要答疑优先。
2. `需求分析word正式版.doc` 是需求分析说明书的权威版本。
3. README、schema.sql、关键 Java 代码和截图用于判断真实实现。
4. 当前 PPT 草稿和页面视觉图只作为覆盖范围参考，不要沿用它的低质视觉风格，也不要被它的页序限制。

任务目标：

请输出一份“给豆包的 PPT 生成包”，包括：

1. 一段可以直接复制给豆包的总提示词。提示词开头请明确写：“请严格参考老师要求和我同步上传的资料，为《基于 PostgreSQL 的数字图像集成管理系统》生成数据库系统课程设计答辩 PPT。”
2. 一份给豆包的资料上传清单，说明哪些文件必须上传、哪些截图适合放在哪些页面。
3. 一份 PPT 策划方案，包括页数建议、每页标题、每页讲什么、每页放什么图、每页应避免写什么。
4. 一份页面文案草稿，要求少字、适合 PPT，不要报告式长段落。
5. 一份视觉设计建议，要求豆包发挥审美，但必须围绕数据库课程设计，不做廉价科技风、堆卡片、花哨渐变、AI 味过重的模板。
6. 一份 15 分钟答辩节奏建议。PPT 讲述建议 10 到 11 分钟，演示 3 到 4 分钟，留出问答余量。
7. 一份演示路线，先讲 PPT，再运行 JAR 或 Windows portable exe，重点演示数据库初始化、目录扫描入库、关键词/NL2SQL 搜索、版本历史和交付包。

评分导向：

PPT 必须直入数据库含金量。评分依据是数据库设计 30、功能设计 20、后台程序设计 15、界面设计 15、报告表述水平 10、PPT 表达能力 10。请让豆包把数据库设计作为主线，而不是把 PPT 做成普通软件介绍。

必须讲清楚但不要写得太满：

1. 系统定位：JavaFX + PostgreSQL 桌面端数字图像管理系统。
2. 数据库设计：13 张表，19 个索引（18 个普通索引 + 1 个唯一部分索引），4 个视图，4 个函数，5 个触发器，5 个存储过程，递归 CTE。
3. ER/关系模式：directories 自引用，images 主表，tag_categories/tags/image_tags 多对多，ai_analysis_results 一对一，image_versions 一对多，operation_logs 审计。
4. 真实功能：完整磁盘目录树懒加载、缩略图/元数据/bytea、AI 标签、关键词搜索、NL2SQL 搜索、版本历史、幻灯片音乐、数据库初始化向导、离线降级、HikariCP、PreparedStatement、事务回滚。
5. AI 与 NL2SQL：AI 结果先落库，查询走 `v_image_search`，只允许 SELECT，只读连接、超时、限行。
6. 界面证据：使用真实截图，不要用空泛图标替代真实界面。
7. 运行交付：JAR、Windows portable zip/exe、源码包和验证日志。

真实性边界：

WebDAV/云端只作为扩展预留。不要写成完整主流程。语音搜索、全网全盘搜索、SQLite 多数据库后端等只能作为后续展望或教师建议，不要写成已经实现。AI 需要用户自行配置 OpenAI-compatible endpoint 和密钥。

请注意：

不要让豆包照抄当前 PPT 的设计。当前 PPT 只能用来判断已经覆盖了哪些内容。新的 PPT 应该更像一次正式数据库课程答辩，视觉要干净、有层次、有真实截图、有数据库对象图，不要低饱和一眼模板感，不要满屏小字。

请直接输出“给豆包的交付包内容”，不要向我提问。
