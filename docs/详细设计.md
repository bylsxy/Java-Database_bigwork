## 2. 类设计

### 2.1 Model 层（数据模型）

#### ImageFile (record)

使用 Java 25 的 **Record** 类型定义不可变数据模型，体现"代码即文档"。

```java
/**
 * 图片文件实体 — 对应数据库 images 表的一条记录。
 * 使用 record 确保不可变性，减少样板代码。
 *
 * @param id          数据库自增主键
 * @param fileName    文件名（含扩展名），如 "photo.jpg"
 * @param filePath    文件在磁盘上的完整路径
 * @param directoryId 所属目录的数据库 ID
 * @param fileSize    文件大小（字节）
 * @param width       图片宽度（像素）
 * @param height      图片高度（像素）
 * @param format      图片格式（JPG/PNG/GIF/BMP）
 * @param thumbnail   缩略图二进制数据（bytea），可能为 null
 * @param createdAt   首次录入时间
 * @param modifiedAt  最后修改时间
 * @param deleted     是否已逻辑删除
 */
public record ImageFile(
    int id,
    String fileName,
    String filePath,
    int directoryId,
    long fileSize,
    int width,
    int height,
    String format,
    byte[] thumbnail,
    LocalDateTime createdAt,
    LocalDateTime modifiedAt,
    boolean deleted
) {
    // Flexible Constructor Body (JEP 513): 
    // 在调用 canonical constructor 之前进行参数校验
    public ImageFile {
        if (fileName == null || fileName.isBlank()) {
            throw new IllegalArgumentException("文件名不能为空");
        }
        if (filePath == null || filePath.isBlank()) {
            throw new IllegalArgumentException("文件路径不能为空");
        }
    }
    
    /** 获取不含扩展名的主文件名 */
    public String baseName() {
        int dotIndex = fileName.lastIndexOf('.');
        return dotIndex > 0 ? fileName.substring(0, dotIndex) : fileName;
    }
    
    /** 获取文件扩展名（含点号），如 ".jpg" */
    public String extension() {
        int dotIndex = fileName.lastIndexOf('.');
        return dotIndex > 0 ? fileName.substring(dotIndex) : "";
    }
    
    /** 格式化文件大小为用户友好的字符串（KB 或 MB） */
    public String formattedSize() {
        if (fileSize >= 1024 * 1024) {
            return "%.2f MB".formatted(fileSize / (1024.0 * 1024.0));
        }
        return "%.1f KB".formatted(fileSize / 1024.0);
    }
}
```

#### ImageDaoImpl 关键方法实现逻辑

```
findByDirectoryId(directoryId):
    SQL: SELECT * FROM v_active_images WHERE directory_id = ?
    用途: 加载某目录下所有活跃图片
    
updateFileName(imageId, newFileName):
    SQL: UPDATE images SET file_name = ?, file_path = ? WHERE id = ?
    注意: 触发器会自动记录重命名日志
    
softDelete(imageId):
    SQL: UPDATE images SET is_deleted = TRUE WHERE id = ?
    注意: 触发器会自动记录删除日志

insert(image):
    SQL: INSERT INTO images (...) VALUES (?, ?, ...) RETURNING id
    用途: 插入新图片记录，返回自增 ID
    注意: 使用 PreparedStatement.setBytes() 设置 bytea 参数
```

### 2.3 Service 层

#### ImageServiceImpl 关键业务逻辑

```
batchRename(images, prefix, startNumber, digitCount):
    1. 获取数据库连接
    2. connection.setAutoCommit(false)  // 开启事务
    3. for 每张图片:
       a. 生成新文件名: prefix + padLeft(startNumber + i, digitCount) + extension
       b. 在磁盘上执行 Files.move(oldPath, newPath)
       c. 调用 imageDao.updateFileName(id, newFileName)
    4. connection.commit()  // 提交事务
    异常处理:
       catch → connection.rollback() → 恢复已重命名的磁盘文件 → 抛出异常
    finally:
       connection.setAutoCommit(true)

deleteImages(images):
    1. 弹出确认（Controller 层已确认）
    2. 获取数据库连接，开启事务
    3. for 每张图片:
       a. imageDao.softDelete(id)  // 数据库逻辑删除
       b. Files.delete(path)       // 磁盘物理删除
    4. 提交事务
    
loadImagesFromDirectory(directoryPath):
    1. directoryDao.findOrCreate(directoryPath)  // 确保目录在数据库中
    2. 扫描磁盘目录，获取所有图片文件列表
    3. 与数据库中的记录对比:
       a. 磁盘有数据库没有 → 新增到数据库
       b. 数据库有磁盘没有 → 标记为已删除
       c. 两边都有 → 比较修改时间，必要时更新
    4. 返回完整的图片列表（含数据库 ID 和缩略图）
```

## 3. JavaFX 界面技术实现

### 3.1 FXML 布局方案

| 界面 | 根容器 | 核心组件 | 说明 |
| :--- | :--- | :--- | :--- |
| MainView.fxml | BorderPane | TreeView (left), ScrollPane > FlowPane (center), HBox (bottom) | 左中下三区域布局 |
| SlideshowView.fxml | BorderPane | StackPane > ImageView (center), VBox (bottom) | 中央大图+底部控制栏 |
| RenameDialog.fxml | VBox | TextField, Spinner, Label | 模态对话框 |

### 3.2 缩略图渲染策略

```
1. 磁盘文件 → ImageIO/JavaFX Image 加载（后台线程）
2. 原始尺寸 → 等比缩放到 120×120 区域内
   缩放算法: 
     ratio = min(120/width, 120/height)
     newWidth = width * ratio
     newHeight = height * ratio
3. 缩略图 → 转为 byte[] → 存入数据库 bytea 字段（首次加载时缓存）
4. 后续加载 → 优先从数据库 bytea 读取缩略图（避免重复读大文件）
5. UI 展示 → 每个缩略图卡片:
   ┌─────────────┐
   │  VBox        │
   │  ┌─────────┐ │
   │  │ImageView│ │  ← 120×120 区域，图片居中
   │  └─────────┘ │
   │  [文件名]    │  ← Label，居中对齐
   └─────────────┘
```

### 3.3 目录树构建

```
1. TreeView<DirectoryNode> 的根节点: "我的电脑"
2. 列出 File.listRoots() → 作为根节点的子节点（C:\, D:\ ...）
3. 使用 LazyLoading 策略：
   - 初始只加载根 → 子目录为 "虚拟节点"
   - 用户展开时 → 替换虚拟节点 → 加载真实子目录
   - 好处：避免一次性加载整个磁盘目录结构
4. TreeCell 自定义渲染：📁 图标 + 目录名
5. 选中变化监听：tree.getSelectionModel().selectedItemProperty().addListener(...)
```

### 3.4 选中交互实现

```
多选机制:
├── 单击（无修饰键） → 清除所有选中 → 选中当前图片
├── Ctrl + 单击      → 切换当前图片的选中状态（不影响其他）
├── 鼠标拖拽框选     → 监听 MOUSE_PRESSED/DRAGGED/RELEASED
│                       → 计算矩形区域
│                       → 遍历所有缩略图判断是否在框内
│                       → 框内的全部选中
└── 点击空白处       → 清除所有选中

视觉反馈:
├── 选中 → 添加 CSS class "selected" → 蓝色边框 + 浅蓝背景
└── 未选中 → 移除 CSS class → 默认样式
```

## 4. 代码质量保障策略

### 4.1 命名规范

| 元素 | 规范 | 示例 |
| :--- | :--- | :--- |
| 类名 | PascalCase, 名词 | `ImageFile`, `MainController` |
| 接口名 | PascalCase, 形容词或名词 | `ImageDao`, `ImageService` |
| 方法名 | camelCase, 动词开头 | `findById()`, `loadImagesFromDirectory()` |
| 常量 | UPPER_SNAKE_CASE | `MAX_THUMBNAIL_SIZE`, `DEFAULT_PLAY_INTERVAL` |
| 局部变量 | camelCase | `currentIndex`, `thumbnailData` |
| 包名 | 全小写 | `com.imagemanager.dao` |

### 4.2 注释规范

1. **类级别**：每个类头部使用 Javadoc，说明"这个类是做什么的"、"谁在什么场景下使用它"
2. **方法级别**：每个 public 方法使用 Javadoc，说明参数、返回值、可能抛出的异常
3. **关键逻辑**：在复杂算法或不直观的代码段前使用行注释，解释"为什么这样做"而不是"做了什么"
4. **TODO 标记**：使用 `// TODO: 描述` 标记待完成或需改进的地方

### 4.3 异常处理策略

```
层级           处理方式                  说明
────────────   ──────────              ──────
DAO 层         捕获 SQLException       → 包装为自定义异常并抛出
                                      → 记录 SQL 和参数到日志
Service 层     捕获 DAO 异常            → 执行事务回滚
                                      → 补偿磁盘操作（如恢复文件名）
                                      → 包装为业务异常并向上抛出
Controller 层  捕获 Service 异常        → 使用 AlertUtil 显示用户友好的错误信息
                                      → 记录完整错误信息到日志文件
                                      → 绝不向用户暴露堆栈信息
```

### 4.4 资源管理

- 所有 `Connection`, `PreparedStatement`, `ResultSet` 使用 **try-with-resources** 自动关闭
- 应用退出时调用 `DatabaseConnection.close()` 关闭连接池
- 大图 `Image` 对象在切换后及时解除引用，交给 GC 回收
- 缩略图生成在后台线程执行，避免阻塞 UI 线程

### 4.5 线程安全

- JavaFX 要求所有 UI 更新在 **JavaFX Application Thread** 上执行
- 耗时操作（如图片加载、数据库查询）使用 `Task` 或 `CompletableFuture` 在后台执行
- 使用 `Platform.runLater()` 将结果回调到 UI 线程
- HikariCP 连接池本身是线程安全的

## 5. 应用变化的数据库调整方案

### 5.1 变化场景分析

| 变化场景 | 影响分析 | 调整方案 |
| :--- | :--- | :--- |
| **新增图片格式支持（如 WebP, HEIC）** | format 字段值范围扩大 | 无需改库表结构，format VARCHAR(10) 已足够。只需修改应用层的格式判断逻辑 |
| **新增图片标签/分类功能** | 需要新的数据实体和关联关系 | 新增 `tags` 表 (id, tag_name) 和 `image_tags` 关联表 (image_id, tag_id)，多对多关系。不影响现有表结构 |
| **文件名长度扩展** | 当前 VARCHAR(255) 可能不够 | 将 file_name 改为 TEXT 类型。实际影响极小，因为 PostgreSQL 的 TEXT 和 VARCHAR 性能一致 |
| **支持多用户** | 需要用户体系和权限控制 | 新增 `users` 表，在 images 和 directories 表中新增 `owner_id` 外键。视图中增加 WHERE owner_id = ? 条件 |
| **EXIF 元数据存储** | 新增非结构化数据存储需求 | 在 images 表中新增 `exif_data JSONB` 字段，利用 PostgreSQL 的 JSONB 支持灵活存储 |
| **图片版本管理（历史版本）** | 需要记录同一图片的多个版本 | 新增 `image_versions` 表 (id, image_id, version_number, file_path, thumbnail, created_at)，与 images 表为 1:N 关系 |
| **回收站功能（延迟物理删除）** | 逻辑删除后需要一个"回收站"界面 | 当前的 `is_deleted` 字段已支持，只需新增回收站视图和"恢复"操作。可增加 `deleted_at` 时间戳字段用于定期清理 |

### 5.2 数据库迁移策略

对于每次模式变更：
1. 编写 SQL 迁移脚本（ALTER TABLE / CREATE TABLE）
2. 在 `sql/` 目录下按版本号命名（如 `V002_add_tags.sql`）
3. 测试迁移脚本的前向兼容性（旧数据不丢失）
4. 更新文档中的 ER 图和表结构说明

| 编号 | 测试项 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| TC-001 | 目录树加载 | 启动应用 | 显示本机所有磁盘根目录 |
| TC-002 | 缩略图预览 | 点击有图片的目录 | 预览区显示所有图片的缩略图 |
| TC-003 | 单选图片 | 点击一张缩略图 | 该图高亮，状态栏显示"选中1张" |
| TC-004 | Ctrl多选 | Ctrl+点击3张 | 3张高亮，状态栏显示"选中3张" |
| TC-005 | 框选 | 拖拽框住多张 | 框内图片全部高亮 |
| TC-006 | 删除 | 选中后右键删除 | 弹出确认→确认后图片消失 |
| TC-007 | 复制粘贴 | 复制→切换目录→粘贴 | 图片出现在新目录 |
| TC-008 | 单张重命名 | 选中1张→重命名 | 文件名更新 |
| TC-009 | 批量重命名 | 选中5张→批量重命名 | 按规则统一命名 |
| TC-010 | 幻灯片播放 | 双击图片 | 打开播放窗口 |
| TC-011 | 幻灯片切换 | 点击前后按钮 | 图片切换，边界有提示 |
| TC-012 | 自动播放 | 点击播放 | 每1秒自动切换 |
| TC-013 | 缩放 | 放大/缩小按钮 | 图片缩放，信息条更新百分比 |
